# Milestone 07 human testing

Status: **partially implemented; full milestone acceptance and physical testing
pending**. Session creation, LAN source sync, restart and local output are available
through the CLI. Local development artifacts remain unimplemented. The local listener is opt-in.

From the Platform root, run the isolated real-stack check:

```sh
bash tests/e2e/07-cli-dev.sh
bash tests/e2e/07-local-grant.sh
RINGFOUR_TEST_OFFLINE_EXPIRY=1 bash tests/e2e/07-cli-dev.sh
```

It requires Docker, `.auth.env` and an existing CLI login. It builds temporary
API, daemon and Runner images, and runs an isolated PostgreSQL database. It
creates a session, obtains a local grant, and checks the daemon certificate
fingerprint. With the Platform stopped, it sends a source snapshot over local
HTTPS, retries the same request, restarts the daemon and retries again. After
Platform restart it waits for the generation report, checks that the source
marker did not enter Platform operation payloads, then requests session closure
while the daemon is offline and waits for cleanup after reconnection. Temporary
containers, volumes and network are removed. The CLI test also verifies session creation,
unchanged-source detection, a file deletion, execution, local output and closure.
It checks rejection of a stale sync through an authenticated, pinned local
connection; restarts daemon and Runner and runs the recovered workspace; and
checks that source-only changes reuse the environment. It then syncs a changed
lock referencing a hash-pinned test wheel and verifies the mission can import
the installed dependency. No physical robot is used.

The third command uses the minimum five-minute session lifetime. It starts a
long-running development mission, stops the Platform, waits for Runner to
stop the mission and remove its workspace, then restarts the Platform and waits
for the session to reconcile to `expired`. Allow several minutes for it to
finish. Its resources are isolated and removed on exit.

For protocol-level inspection with an authenticated client and an enrolled,
online robot, create a session using `POST /v1/robots/{robot_id}/dev-sessions`
with an `Idempotency-Key` and body `{"ttl_seconds":3600}`. Read
`GET /v1/dev-sessions/{session_id}` until the state is `ready`. Creation returns
202 before the Runner confirms the workspace.

The local listener must be enabled with `RINGFOUR_LOCAL_DEV_ENABLED=true`. Its
port defaults to 8084; `RINGFOUR_LOCAL_DEV_HOST`, `RINGFOUR_LOCAL_DEV_PORT`,
`RINGFOUR_LOCAL_TLS_PATH` and optional `RINGFOUR_LOCAL_DEV_URL` configure its
listener, persistent certificate and advertised URL. The client obtains a grant
and verifies the Platform-supplied certificate fingerprint **before** sending
its local token. The CLI performs this verification; do not bypass certificate
verification when sending a bearer token.

The `PUT /v1/local/dev-sessions/{session_id}/source` body contains a complete
ZIP snapshot, a manifest and the prior generation. A 200 response means the
Runner committed it locally. The local session check reports `generation` and
`report_pending`; the Platform session generation may lag while offline. Retry
`503 sync_pending` with the same idempotency key and body. A different body
with that key is rejected, as are stale generations. Sessions retain at most 20
committed generations before closure. A source sync does not execute code.

Close the session using `DELETE /v1/dev-sessions/{session_id}` with a separate
idempotency key; read the session until `closed`. When the robot is offline,
expect `closing` until it reconnects. Credential-rotation revocation and
bounded grant-history cleanup remain incomplete; do not treat this as a
completed or physically validated milestone.

## CLI workflow

From a mission directory, using an installed `ringfour-cli` and a selected
organization:

```sh
ringfour-cli dev start --robot <robot-name-or-id> --daemon-url https://<robot-lan-address>:8084
ringfour-cli dev sync
ringfour-cli dev restart --follow
ringfour-cli dev logs --follow
ringfour-cli dev status
ringfour-cli dev stop
```

If the daemon advertises its reachable LAN URL, omit `--daemon-url`. If the CLI
is not installed, replace `ringfour-cli` with
`uv run --project /absolute/path/to/platform/apps/cli ringfour-cli`. Pass `--org`
if no organization is selected; pass `--robot` when the project remembers more
than one target. The visible `ringfour.context.json` stores session and target
IDs, never the local token. `dev sync` excludes hidden files, `__pycache__` and
the context file, and skips an unchanged snapshot. `dev restart --follow` starts the latest synced generation and streams its
output directly from the robot; `dev logs --follow` reads the latest development
run. Interrupting the log follower leaves the run active. Edit the source, run
`dev sync`, then `dev restart --follow` again to switch generations. A sync
alone never starts code. Closing stops the development execution and deletes
the local workspace.
The private Runner execution slice can be checked with
`bash tests/e2e/07-runner-restart.sh`. It runs only a disposable local Runner,
checks source-only environment reuse and lock reprovisioning, then restarts the
Runner and verifies an interrupted execution is not repeated. The full-stack CLI test exercises that workflow separately.
