# Human testing — milestone 06 missions

Status: **local integration tested; physical Balena acceptance pending**. Use
an isolated test robot. The live stack and device images are not updated just
by changing this repository. Follow `docs/development.md` to build the current
API, daemon and Runner; use a real enrolled robot or the separate local robot
compose. The CLI requires Auth0 login and a selected organization. Do not put
credentials in mission files.

## Create a mission and prepare it

In a new folder (or the existing empty `../missions/hello`) create:

```toml
# mission.toml
schema_version = 1
name = "hello"
entrypoint = "main.py"
python_requirement = ">=3.13,<3.14"
lock_file = "requirements.txt"
```

```python
# main.py
import time
print("hello from my mission", flush=True)
while True:
    time.sleep(1)
```

Create an empty `requirements.txt`. For dependencies use a UTF-8, hash-pinned
requirements lock compatible with uv. The Runner's Python must satisfy the
constraint. The optional `robot_profile_ref` references an external robot
profile; Ringfour does not create or own it. Hidden files and `mission.toml`
are excluded from the immutable source bundle.

```bash
ringfour-cli login
ringfour-cli org select <organization-id>
ringfour-cli ../missions/hello push --robot <robot-id> --idempotency-key hello-push-1
```

The result contains `mission_revision_id`, `deployment_id` and
`operation_id`. Preparation is asynchronous; `push` does **not** start the
mission. If `--robot` is omitted, `RINGFOUR_ROBOT_ID` is used, or the CLI
selects the sole online enrolled robot in the organization. Otherwise specify
`--robot`. Check:

```bash
ringfour-cli mission status <deployment-id>
ringfour-cli robot operation <robot-id> <operation-id>
```

Wait for `observed_state: ready`, `candidate_revision_id: null`, and the
selected revision to match the returned mission revision. A failed candidate
reports `last_error`; the prior selected revision remains selected. Fix the
source and retry with a new key. Reusing the exact key with unchanged inputs
replays a submission; do not reuse it for different input.

The individual publication and deployment steps are also available:

```bash
ringfour-cli mission publish ../missions/hello --idempotency-key hello-publish-2
ringfour-cli deploy <mission-revision-id> --robot <robot-id> --idempotency-key hello-deploy-2
```

Deploy rejects an active script or mission; explicitly stop it first. The
Platform also rejects stale mission versions and cross-organization access.

## Lifecycle and inspection

```bash
ringfour-cli mission start <deployment-id> --idempotency-key hello-start-1
ringfour-cli mission status <deployment-id>
ringfour-cli execution show <execution-id>
ringfour-cli logs <execution-id>
ringfour-cli mission restart <deployment-id> --idempotency-key hello-restart-1
ringfour-cli mission stop <deployment-id> --idempotency-key hello-stop-1
```

Start and restart return a reserved execution ID. It can briefly return 404
until the durable action creates the execution; inspect the operation and retry.
The execution shows the actor, deployment and immutable mission revision.
Restart stops the old process and creates a **different** execution ID. Stop
sets desired state to stopped; if the daemon is offline, reconnect it and wait
for the observed terminal state. A stop can supersede a pending start or
restart. Repeating a request with the same key returns the original IDs.

While the long mission is running, try `ringfour-cli run <script.py> --robot
<robot-id>` and confirm `execution_conflict`; there must not be two active
processes. Stop the mission to finish the test. A Runner restart can terminate a
process with `interrupted_unknown_outcome`; the Platform must not silently run
it again. Start again only with an explicit new action. There is no automatic
restart policy, and these virtual environments are not security sandboxes.

For the automated isolated acceptance setup, see `tests/e2e/06-missions.sh` and
`docs/evidence/06.md`. External physical-device results must be recorded there
separately; do not treat local container results as evidence from Balena.
