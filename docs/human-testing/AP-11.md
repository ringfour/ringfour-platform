# AP-11 Console Apps acceptance

AP-11 replaces the mission-centered primary Console workflow with authenticated
Apps, Store and Logbook views. The user confirmed the current browser smoke:
views render and an App can be imported. Visual refinement is deferred. Full
multi-role and two-workspace acceptance remains part of AP-13.

## Local acceptance

From `ringfour-platform`:

```sh
npm --prefix apps/console run typecheck
npm --prefix apps/console test
npm --prefix apps/console run build
```

## Browser checklist

1. Sign in to a workspace with no robots. Home shows the empty state. In a
   workspace with multiple robots, Home lists each robot, the last presence and
   inventory observation, active App runs and failed/interrupted runs.
2. Take a robot offline. Refresh Home and Robots. It must show offline or
   unknown status and last-known activity with its time; it must not claim the
   device is currently running an App from stale data.
3. Open an App Store release. Confirm its publisher, immutable release,
   description, required and optional capabilities. Select each robot and run
   compatibility preview. Verify missing capability and missing inventory
   results are visible and do not enable install.
4. Import a listed release and a directly shared release into the destination
   workspace. Confirm the share ID is required for direct lookup and that the
   imported revision appears only in the destination workspace.
5. Check the compatibility preview, then change robot inventory before
   installing. The API response must remain authoritative; display its refusal
   and do not claim that installation succeeded.
6. Install an App. Refresh while its operation is queued, accepted or staging;
   follow the operation and distinguish those states from installed. Try two
   eligible robots and confirm the intended robot is selected explicitly.
7. Configure a release using its typed fields, including an invalid value.
   Confirm client constraints are shown and the server's schema refusal is
   displayed. Update to another revision and verify the installed/candidate
   state and configuration revision.
8. Start and stop an App as an operator. Verify the run state refreshes and
   links to its robot. A role without operation authority must not get enabled
   mutation controls; server-side refusal remains visible if authority changes
   after loading.
9. Open the App Logbook from the App, robot and Home. Filter by App, robot and
   state. Open a run and inspect stdout, stderr, events, artifact download and
   robot link. Verify submitted HITL stays submitted until device confirmation.
10. Switch between two workspaces containing different robots, Apps, runs and
    decisions. No list, selection, filters or operation state from the former
    workspace may appear in the latter.
11. Use only the keyboard through navigation, filters, Store compatibility,
    typed configuration, run controls and Logbook. Confirm visible focus and
    sensible focus order.

If a stack reload or rebuild is needed to expose the Console/API changes, the
operator performs that operation under `AGENTS.md`.
