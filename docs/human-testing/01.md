# Human testing guide — milestone 01 (identity)

Everything a human can use and verify after milestone 01: CLI login/logout and
organization management over real Auth0, and Console sign-in/sign-up with
organization and membership views.

## Prerequisites (one-time, already done on this machine)

- Docker Desktop running; repo checked out.
- `.auth.env` at the repo root contains `AUTH0_DOMAIN`, `AUTH0_AUDIENCE`,
  `AUTH0_CLI_CLIENT_ID`, `AUTH0_WEB_CLIENT_ID`.
- Auth0 tenant configured (done during this milestone's acceptance):
  - API `https://api.ringfour.eu`: RS256, **Allow Offline Access**, and
    Settings → Application Access Policy → User-Delegated Access = **All apps allowed**.
  - Ringfour CLI (Native): grant type **Device Code** enabled.
  - Ringfour Web (SPA): Allowed Callback/Logout URLs include `http://localhost:5173`.
- Two test accounts (email+password) registered in the tenant.

## 1. Start the stack

```bash
docker compose -f infra/compose/docker-compose.yml up -d --build
curl -s localhost:8080/health/ready    # {"status":"ok",...}
```

Sanity check — the API enforces authentication:

```bash
curl -s localhost:8080/v1/me
# {"error":{"code":"unauthenticated","message":"A valid access token is required.",...}}
```

## 2. CLI: log in as account 1

```bash
cd apps/cli
set -a; . ../../.auth.env; set +a
export RINGFOUR_AUTH0_DOMAIN="$AUTH0_DOMAIN"
export RINGFOUR_AUTH0_CLIENT_ID="$AUTH0_CLI_CLIENT_ID"
export RINGFOUR_AUTH0_AUDIENCE="$AUTH0_AUDIENCE"

uv run ringfour-cli login
```

- The CLI prints a verification URL and a user code (e.g. `ABCD-EFGH`) and
  opens your default browser.
- Approve the code and sign in as **account 1**.
- Expected: `Logged in. Credentials stored in the OS credential store.`
  (Tokens live in the macOS Keychain; nothing secret touches the config file.)

## 3. CLI: verify identity is stable

```bash
uv run ringfour-cli whoami
```

- Expected: a user UUID and a (possibly empty) memberships table.
- Run it again — the user id must be **identical** (subject → one local user).

## 4. CLI: organizations

```bash
uv run ringfour-cli org create "Acme Robotics"   # you become its owner
uv run ringfour-cli org list                      # the org appears with role owner
uv run ringfour-cli org select <org-id>           # persisted selection, marked * in list
uv run ringfour-cli whoami                        # membership now visible
```

## 5. Cross-org isolation with account 2

The keyring holds one credential set per tenant; logging in again replaces it.
To force a **different** account (your browser's Auth0 SSO session would
otherwise silently reuse account 1):

```bash
uv run ringfour-cli login --no-browser
```

- Do **not** let it open your default browser; instead copy the printed link
  into an **incognito/private window**, enter the code, and sign in as
  **account 2**.
- Then:

```bash
uv run ringfour-cli whoami       # a DIFFERENT user id than step 3, no memberships
uv run ringfour-cli org list      # empty — account 2 sees nothing of account 1
```

- Expected isolation behavior: account 2 reading account 1's organization
  members via the API gets **404 not_found** (existence is not leaked), and
  any membership mutation gets 404 as well. (Covered automatically by the
  component tests; optionally verify in the Console by adding account 2 as a
  member — see step 6 — then repeating: the org becomes visible.)

When finished, restore your main credentials:

```bash
uv run ringfour-cli login        # approve as account 1
```

## 6. Console (Authorization Code + PKCE)

```bash
open http://localhost:5173
```

- Unauthenticated: only the sign-in screen renders; **no API calls are made**.
- **Sign up** opens Auth0's registration screen (New Universal Login);
  **Sign in** logs in an existing account.
- After signing in, the Identity view shows your user id, your organizations
  with your role, and lets you **create an organization** (you become owner).
- Click an organization name to **inspect its members**.
- **Sign out** returns to the login screen.
- The Health view (nav) still shows service readiness without product data.

## 7. CLI: log out

```bash
uv run ringfour-cli logout    # removes tokens from the Keychain
uv run ringfour-cli whoami    # fails: "Not logged in. Run `ringfour-cli login` first."
```

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `unauthorized_client: Grant type ... device_code not allowed` | Enable the Device Code grant on the CLI application (Applications → Ringfour CLI → Advanced Settings → Grant Types). |
| `Client ... is not authorized to access resource server` | API → Settings → Application Access Policy → User-Delegated Access = All apps allowed. |
| Login approves as the wrong account | Browser SSO session reused account 1. Use `login --no-browser` + incognito. |
| Console loops back to login | `http://localhost:5173` missing from the SPA's Allowed Callback URLs. |
