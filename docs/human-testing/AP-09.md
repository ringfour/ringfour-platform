# AP-09 — hosted App start/stop

Run this with the combined human pass after AP-10. Automated component and real
protocol acceptance remain implementation checks; this guide is operator confidence.
Use the [AP-07 API deployment](AP-07.md) and the opt-in
[AP-08V topology](AP-08V.md) with the updated API and Daemon. The API
applies AppRunDispatch; Daemon applies SQLite 0019 and negotiates run support.
Preserve enrollment/volumes. Only the operator reloads either live stack.

After installing Robot Check, set API, TOKEN, INSTALLATION, REVISION and
CONFIGURATION (the exact installed configuration revision UUID). Operator,
Developer or Owner membership can run it. Keep the normal Auth0 token private.

```sh
curl --fail-with-body -sS "$API/v1/app-installations/$INSTALLATION/start" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: robot-check-start-1' \
  --data "{\"expected_revision_id\":\"$REVISION\",\"expected_configuration_revision_id\":\"$CONFIGURATION\"}"
```

Save run_id as RUN and operation_id as OPERATION. HTTP 202 and accepted operation
are durable requests. GET /v1/app-runs/$RUN shows running only after actual engine
observation; a short IMU App can already be succeeded by the next poll. Its
snapshot retains exact publisher, import, image and configuration. Inspect
/v1/app-operations/$OPERATION independently.

Repeat the same start and key: receive the original IDs. Reuse the key with a
different expected configuration: idempotency_conflict. Try another start while
active: execution_conflict; neither App nor legacy execution may overlap. Try a
stale installed generation: stale_installation. A separate workspace cannot read
or control this run. Missing fresh capabilities refuse before container creation.

```sh
curl --fail-with-body -sS "$API/v1/app-installations/$INSTALLATION/stop" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: robot-check-stop-1' --data "{\"expected_run_id\":\"$RUN\"}"
```

Stop always names the run. For an already terminal run it succeeds without engine
mutation. For pending launch it cancels before start where delivery permits.
Use a longer configured/test App for active stop and replacement checks; the
20-sample Robot Check often finishes too quickly. Operator replacement of only
the Daemon with its persistent volume must retain container ID/StartedAt, with
no relaunch. Stop afterward must address that same container. Start a new run,
then repeat the old stop: the newer run continues. During an engine/API outage
retain uncertain state and the slot until reconciliation; never infer success
or cancellation from disconnection.

GET /v1/organizations/$ORG/app-runs supports robot_id, installation_id, app_id,
limit and cursor filters. Run output, artifacts and human decisions are AP-10.
The standalone `docker start` demonstration is separate from hosted run acceptance.
