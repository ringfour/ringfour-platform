# AP-12 App CLI acceptance

AP-12 adds authenticated CLI workflows for App discovery, import, installation,
configuration, updates, runs, evidence and robot capability inspection. The
CLI shares the Platform APIs and authorization checks used by Studio. This
guide records the commands and acceptance sequence. Focused CLI tests cover
workspace-scoped installation, App-to-installation resolution, ambiguity
refusal and exact-run stop. Real API/Daemon and multi-user acceptance is part of
AP-13. See the [automated evidence](../evidence/AP-12.md).

## Command reference

From `ringfour-platform`:

```sh
uv run --project apps/cli ringfour-cli app --help
uv run --project apps/cli ringfour-cli app search
uv run --project apps/cli ringfour-cli app show <app-id>
uv run --project apps/cli ringfour-cli app import <revision-id>
uv run --project apps/cli ringfour-cli app imports
uv run --project apps/cli ringfour-cli app install <revision-id> --robot <robot-id>
uv run --project apps/cli ringfour-cli app operation <operation-id> --wait
uv run --project apps/cli ringfour-cli app installations --robot <robot-id>
uv run --project apps/cli ringfour-cli app configure <installation-id> --config values.json
uv run --project apps/cli ringfour-cli app update <installation-id> <revision-id>
uv run --project apps/cli ringfour-cli app start <installation-id>
uv run --project apps/cli ringfour-cli app start <app-id> --robot <robot-id>
uv run --project apps/cli ringfour-cli app run <run-id>
uv run --project apps/cli ringfour-cli app logs <run-id> --follow
uv run --project apps/cli ringfour-cli app artifacts <run-id>
uv run --project apps/cli ringfour-cli app stop <installation-id> --run <run-id>
uv run --project apps/cli ringfour-cli app logbook --app <app-id>
uv run --project apps/cli ringfour-cli robot capabilities <robot-id>
```

For a direct share, pass `--share-id <share-id>` to `app import`, `app install`
or `app update`. `app artifact <run-id> <artifact-id> --output <path>` downloads
one item and verifies its size and SHA-256. Use `app interaction <run-id>
<request-id>` and `app respond <run-id> <request-id> <choice>` for run-scoped
human interactions. A submitted response remains pending until device
confirmation.

## Acceptance sequence

1. Sign in and select a workspace. Confirm `app search` only returns listed
   releases visible through the Store and `app show` reports immutable release
   metadata.
2. Import a listed release. Repeat with a direct-share release using its
   destination-bound share ID. Try the same share from a different workspace;
   the API must refuse it.
3. Install a release on an explicitly selected robot. Follow its operation
   through `app operation --wait`; confirm installation does not create a run.
   Try a second robot name that is ambiguous and verify the CLI requires an ID.
4. Use a JSON object to configure the installation. Submit an invalid value and
   confirm the API's schema refusal is shown. Update to another revision and
   inspect its operation; a failed update must leave the installed binding
   unchanged.
5. Start the installation and record both returned IDs. Read state and output
   by run ID. List/download an artifact and verify the local file matches the
   API size and SHA-256. Filter App Logbook by App, installation, robot and run.
6. Submit a human-interaction response. Confirm the CLI describes it as
   submitted until the device reports it applied. Stop using the exact run ID;
   repeat the old stop request after starting a newer run and verify it does
   not stop the newer run.
7. Run `robot capabilities <robot-id> --revision <revision-id>`. Compare the
   compatibility result with the authoritative install outcome after changing
   inventory. The API/device refusal must take precedence over stale local
   expectations.
8. Repeat as a viewer/operator/developer in two workspaces. Check role-denied
   mutations, workspace isolation, idempotent retries and machine-readable
   errors with `--json` where available.

No Platform or virtual stack reload is part of this CLI guide. The operator
performs any required stack operation under the workspace `AGENTS.md` rule.
