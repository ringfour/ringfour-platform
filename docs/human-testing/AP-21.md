# AP-21 Studio acceptance

Use **cdr** for the main account and **ring1** for the second account (the Outlook
login). Use separate browser profiles or a normal window plus a private window;
separate Unix shells alone do not separate browser login sessions. Record which
account, workspace, robot and release each window is using.

This guide covers Studio interactions. The API/Daemon/CLI publication and failure
matrix remains in [AP-18](AP-18.md). Browser fixtures are regression checks; they
are not evidence that these live journeys have passed.

## Prepare

1. The operator reloads Platform from the Platform root with `./up.sh -d`.
   The default local recipe uses the development target and shows Development.
   If the final AP-18 Daemon fixes have not been deployed, reload ringfour-virtual
   using its documented launcher (`RINGFOUR_ALLOW_DIRTY_APP_SOURCES=true ./up.sh -d`
   when working from these modified local sources). The agent does not run these
   stack operations under the workspace rule.
2. Open Studio at its configured origin and sign in normally with Auth0. Do not
   use the screenshot fixture for live acceptance. Confirm the workspace selector under My profile
   and navigation ordered Home, Apps, App Store, Robots, Logbook.
3. Use Camera Snapshot Loop on virt2, a second enrolled robot with the same App,
   an authorized private/shared App, an unsupported release and an empty workspace.
   A second physical/simulated robot is needed for the multi-robot live gate.
   Keep missing fixtures marked pending instead of treating one robot as two.
4. For an official public release, configure the trusted publisher UUID as
   `APPS_OFFICIAL_PUBLISHER_ORGANIZATION_ID` (and a matching publisher-bound
   registry policy when used). Then follow AP-18 to publish it explicitly listed.
   A working reachable registry is required. The Ringfour label comes from this
   server entitlement; ordinary private Apps should show their publisher name.

## Navigation and workspace isolation

- Open each main destination with the normal link, in a new tab, and by copying
  its URL into a fresh tab. Refresh App Settings, Files and Activity with an exact
  installation selected; the App and robot must stay selected.
- Visit `/logbook?workspace=W` and `/logbook/U?workspace=W#output`. They normalize
  to `/runs` and `/runs/U` while retaining query/fragment and replacing the alias
  history entry. An unknown path must show Page unavailable, not Home.
- Search/filter Apps or Robots, scroll, open an item, then use browser Back and
  the parent collection link. The original collection filters and scroll should
  return. Fixed `/robots/enroll` must show enrollment, not a robot named enroll.
- Switch workspace while inspecting a detail. Return to that collection in the
  new workspace. No old robot, operation, pending answer or cached data should
  flash. A robot or installation from the other workspace must be unavailable.
- With unsaved Startup configuration or Live settings, try a section link,
  sidebar link, browser Back, browser Forward and workspace change. Reject the
  prompt: keep both route and edits. Accept it: navigate and discard the edits.
  Refresh/close also warns. Saving must not trigger a discard prompt.

## Home and robots

- Home leads with compact workspace robot rows, online/offline state, last seen
  and current or explicitly last-known work. An idle connected robot offers
  Choose an App scoped to that robot. Active work opens its exact installation.
- Pending decisions appear above the robots. Use cdr to submit a choice and
  verify submitted versus device-confirmed behavior. Use ring1 without mutation
  authority to check unavailable actions and server refusals.
- Repeated failures of the same App/robot form one attention item with a count
  and a link to the exact latest failed run. Full records remain in Logbook.
- The empty workspace has Connect a robot and local simulator instructions.
  There is no duplicate Apps-in-use panel or inline timeline on Home.
- Robots → Connect a robot opens `/robots/enroll`. Pair a new robot, then an
  existing unregistered robot. An expired code stays editable with a clear error.
  After enrollment from a Store listing, return to that listing with its robot.
- Robot detail → Device access opens `/robots/R/credentials`; browser Back and
  refresh retain the correct robot. No second workspace selector or Manage mode
  should appear. Owner token issuance/rotation shows its secret once; dismissal
  removes it. Test revocation only on the intended disposable credential.
- Device details show the same `inventory.current` profile/capabilities used by
  compatibility. Unavailable/offline inventory is qualified as last known.
  Compare camera instance names with Store compatibility. Missing observations
  must not be reported as a fabricated zero capability inventory.

## Store and installation

- Store cards show one App identity, purpose and publisher; Ringfour is shown
  only for the server-entitled publisher. Authorized imported private Apps with
  no installations remain discoverable. Direct-share import is secondary.
- Open Camera Snapshot Loop's listing. Required and optional capabilities are
  distinct; technical release details are expandable. The current v1 manifest
  has no publisher artwork/screenshots/release-note fields. The supplied Studio
  design's bundled artwork identifies the reference App families; other Apps use
  the shared fallback icon. Camera imagery on the listing is explicitly labelled example output;
  it must never appear as a real result in Files. Release descriptions come from
  the actual manifest, without invented release notes.
- Install opens a robot picker. Even with one robot, inspect its preselection.
  Choosing another robot automatically checks compatibility. Missing capabilities
  explain the failure and disable installation; missing/stale inventory stays
  unknown. With no enrolled robots, Enroll a robot returns to this listing.
- The same release installed on the selected robot immediately offers Open App
  with the exact installation. Another installed release offers Update on the selected robot.
  Neither repeats installation or starts a run.
- Submit installation, then refresh or dismiss progress. The operation remains
  in the URL/listing; its candidate also restores progress. Offline delivery is
  pending, not successful. Open App appears from the confirmed binding.
- Cancel/Escape closes the picker and returns focus to its trigger. Browser Back
  closes a picker opened from the listing. Tab/Shift+Tab remain within the modal.

## App operation, settings and results

- Apps lists current installations grouped by App, with a robot filter. An
  imported-only App belongs in Store. Multiple targets require explicit selection
  before Start, Stop, Save, Update, Rollback or Uninstall.
- Open the App from Robot B, change to Settings and refresh. Robot B must remain
  selected; its changes must not affect virt2. Check float startup values (for
  example 2.5 if permitted by the manifest) and Live settings separately.
- Start the selected App, observe its actual run, stop that exact run, and confirm
  the live projection updates without replacing the entire page. Another App
  holding the slot links to its exact installation. Offline state is last known.
- Files lists published results by filename/folder, target/run, time and size.
  Open an actual photo from Camera Snapshot Loop, inspect the preview, then
  download it. Receipt size/hash verification applies to both. SVG/HTML are not
  inline image previews. Repeated paths from different runs stay distinguishable.
- Activity groups related events by run with one Open run link. Expand to see
  original event IDs. Installation/settings events without a run remain readable.

## Updates, rollback and removal

- Review update names App, robot, installed and selected releases. Review startup
  values, live settings defaults and changed requirements before applying. For
  a private shared release, import it first or supply its share ID when required.
- An active robot run blocks changes. A failed pull/staging request keeps the
  prior binding usable and its error visible. Refresh restores operation state;
  the displayed installed release changes only after device confirmation.
- Rollback offers retained configurations that the API has confirmed applied.
  Choose a prior configuration, review it and apply while stopped. The App stays
  stopped. Run history keeps its original release/configuration snapshots.
- Uninstall remains unavailable until the current connected Daemon confirms
  support. Confirmation names App/robot and explains retained files/history.
  Remove only one of the two installations. Check the other robot, Store library,
  old run and Files. Reinstall and confirm a new installation identity.
- Switching target clears the previous target's local operation selection. A
  copied operation URL pointing at another installation must show unavailable,
  never a false success for the selected target.

## Logbook, keyboard, narrow layout and production

  time; share/refresh the URL and retain filters. Run links lead to the same
  canonical record from Home, Activity, Robot and Timeline.
- Switch List → Timeline → run → Back; preserve robot/time context. Inspect
  historical event markers without losing original recorded/received times.
- At a narrow viewport, use the menu, target picker, primary action and modal by
  keyboard. Check focus visibility, Escape, focus return, reduced motion and no
  page-wide horizontal overflow. Errors, no results, denied access, offline and
  unknown observation must remain distinct.
- Production uses the Dockerfile `production` target described in
  [Studio README](../../apps/console/README.md). Verify real hosted Auth0 login,
  callback, refresh, logout, direct App deep link and the same-origin `/api/`
  proxy behind the intended HTTPS ingress. There is no development-only block
  or prototype link. A static-container smoke is not hosted Auth0 acceptance.

Record exact deployed revision/build, both account/workspace roles, robot and
installation IDs, release/image digests, commands and results in
[AP-21 evidence](../evidence/AP-21.md). Keep unexercised gates pending.
