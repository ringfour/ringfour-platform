# Verify the Apps contract slices

This slice supplies contracts, not an executable App workflow. Use a checkout
with Node and the contracts package's existing AJV dependency installed. From
`ringfour-platform`:

```sh
npm --prefix packages/contracts test
node packages/contracts/test/apps.test.mjs
node packages/contracts/test/fixtures.test.mjs
```

Expect all tests to pass: 26 App tests (including 19 rejected fixture cases) and
35 legacy/identity-format tests when invoked directly. The npm command may
summarize file results. No stack command is required.

Read `packages/contracts/fixtures/apps/v1/manifest.json`: Robot Check requires
IMU, optionally uses cameras, targets a Linux amd64 digest and defaults
`sample_count` to 1 (valid values 1–20). This is illustrative; do not try to pull
the example image. Compare `canonical.json` for exact serialized content and
SHA-256. `rejected.json` contains complete inputs and expected rejection codes
for future independently implemented readers.

To try a local configuration without editing fixtures:

```sh
node --input-type=module <<'JS'
import {readFile} from 'node:fs/promises';
import {validateManifest, validateConfiguration} from './packages/contracts/test/support/app-manifest.mjs';
const manifest = JSON.parse(await readFile('./packages/contracts/fixtures/apps/v1/manifest.json'));
validateManifest(manifest);
console.log(validateConfiguration(manifest, {sample_count: 3}));
try { validateConfiguration(manifest, {sample_count: 0}); }
catch (error) { console.log(error.message); }
JS
```

Expect `{ sample_count: 3 }` and then `invalid_config` with the violated bound.
The validator does not fill defaults or turn strings into numbers. No App,
installation or run is created. The schema rejects publisher assertions,
entrypoint overrides, socket mounts, unknown capability vocabulary and remote
schema references. The semantic oracle also rejects two targets for the same
OS/architecture and invalid configuration defaults.

Review `docs/apps-contract.md` for the trust boundary: only the enrolled Daemon
receives operator-provided engine authority; App manifests cannot supply engine
settings. Follow `docs/milestones/apps-pivot.md` for remaining AP-01 contracts
before using any future publishing or deployment workflow.


## Verify API/runtime contracts

Read `docs/apps-api-contract.md` and the new App operations in both hosted and
runtime OpenAPI documents. Each is marked `x-implementation-status:
contract-only`; do not send these requests to a running stack yet.

```sh
node packages/contracts/test/apps-api.test.mjs
npm --prefix packages/contracts run test:openapi
```

Expect 61 passing API/runtime tests and 5 OpenAPI tests. The YAML checks require
Python 3 plus PyYAML 6.0.3 (development-only pin in
`packages/contracts/requirements-test.txt`). They check reference targets,
duplicate route keys, path parameters, authentication declarations, required
App mutation retry headers and preserved legacy namespaces. They do not test
live authentication or enforce roles on a server.

Inspect `packages/contracts/fixtures/apps/v1/api.json`. Compare `install_ack`
with `not_yet_installed`: a durable acknowledgement has no observed installed
binding and no run. `staged_update_keeps_v1` retains its old installed revision
while the candidate differs. `observed_run` and `lost_container` retain the same
snapshot/UUID; interruption does not invent a known engine exit or relaunch.
`pending_app_interaction` uses run attribution, with submitted responses staying
pending until confirmed. `errors.json` distinguishes inventory, capability,
platform, pull, ownership/run-precondition and loss outcomes through stable
codes and explanatory details.

`requests.json` supplies complete mutation inputs. A stop names a concrete
`expected_run_id`; it cannot use a dynamic active-run selector. `api-rejected.json`
contains complete invalid examples for future independently implemented
readers. The invariant tests also reject a wrong destination share, grant use
at expiry, applying a binding while a robot is active, changing run attribution,
phase regression and a delayed stop against a later run.

No stack reload is required. At the end of that slice, device negotiation and cross-language readers
remained AP-01 work; the following section records their completion. No
migration or App dispatch is enabled by these checks.

## Verify device negotiation and independent readers

The device contract is `docs/apps-device-contract.md`. Its HTTP routes remain
contract-only. No stack reload is needed, and running stacks do not yet serve
these App routes. Keep using the existing legacy workflows until the later
implementation milestones enable them.

```sh
node packages/contracts/test/apps-device.test.mjs
apps/daemon/.venv/bin/python -m pytest apps/daemon/tests/test_app_protocol.py -q
apps/cli/.venv/bin/python -m pytest apps/cli/tests/test_app_contracts.py -q
npm --prefix apps/console test -- src/lib/app-contracts.test.ts
npm --prefix apps/console run build
```

Expect 39 device schema tests, 24 Daemon reader tests, 14 CLI and 14 Studio tests,
and a passing Console build. The current complete Node corpus is 166 tests;
earlier counts in this guide describe the preceding slices.

Inspect `packages/contracts/fixtures/device/apps/v1/positive.json`: negotiation
names the normal v1 welcome session plus a persistent deployment namespace;
`base101_inventory` supplies the ten advertised capabilities and base camera.
Compare online/offline status: observation timestamps stay unchanged. In
`agent_unavailable_with_cache`, the old reply is only `last_successful`; there
is no current inventory. Optional capability omissions keep a compatible result.
The typed commands remain valid payloads of the original v1 transport schema.

Read `rejected.json` to see unsupported selected versions, duplicate offers,
cache passed as current, missing namespace, dynamic stop, durable registry
credentials and entrypoint overrides rejected. Read `summaries.json` alongside
the CLI and Studio tests to verify they agree on accepted/staged/observed and
failed states. The readers are tested code, not a running command dispatcher.

For normal C# test infrastructure, restore dependencies and run:

```sh
dotnet test apps/api/tests/Ringfour.Api.Tests/Ringfour.Api.Tests.csproj --filter FullyQualifiedName~AppContractFixtureTests
```

When local test sockets are prohibited, use the pure in-process fallback after
restoring the test project:

```sh
bash scripts/check-app-contracts-dotnet.sh
```

Expect eight C# checks: positive/rejected API/device fixture groups, all manifest
semantic fixtures and canonical bytes/digest. No database or stack is started.
The fallback does not execute the rest of the API suite. See the evidence for
the local-cache restore command used in this workspace if NuGet is unavailable.

AP-01's contract gate is complete. AP-02 must add and verify forward migrations
and the shared execution slot before any App records or dispatch are enabled.
Actual Agent inventory and pre-pull checks arrive with AP-03/07/08; this guide
claims no live sensor or container behavior.
