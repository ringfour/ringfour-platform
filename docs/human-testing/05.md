# Human testing — milestone 05 scripts

Milestone 05 runs one trusted Python script on an enrolled robot. It does not
provide mission packaging or `missions/hello push`; those are milestone 06.
Python environments isolate dependencies, not untrusted code. The commands
below run from the platform repository root.

## Setup

Use the Auth0 account and organization from guides 01–02, a paired and online
robot, and a reachable API. The target daemon and Runner must be built from this
milestone and use the same high-entropy `RUNNER_AUTH_TOKEN`. The daemon needs
its persisted identity and a reachable `PLATFORM_API_URL`; Runner needs its own
persistent `/data` and the shared staging volume read-only. Never mount the
container-engine socket. The Platform API needs persistent private storage:

- Local Compose configures `Storage__Backend=filesystem` and
  `Storage__FilesystemRoot=/storage` on a named volume. Rebuilding the stack
  applies new migrations to its existing database; it does not remove volumes.
- A hosted Garage installation uses `Storage__Backend=s3`,
  `Storage__S3__Endpoint`, `Storage__S3__Region` and `Storage__S3__Bucket`.
  Supply AWS-compatible credentials through the SDK's normal credential
  provider chain, not source control. Use HTTPS outside local testing. The
  bucket must be private and available to the API; robots do not receive its
  credentials.

To build and start the local development stack when appropriate:

```bash
export RUNNER_AUTH_TOKEN="$(openssl rand -hex 32)"
docker compose -f infra/compose/docker-compose.yml up -d --build
uv run --project apps/cli ringfour-cli login
uv run --project apps/cli ringfour-cli org list
uv run --project apps/cli ringfour-cli org select <organization-id>
uv run --project apps/cli ringfour-cli robot list
uv run --project apps/cli ringfour-cli robot status <robot-id>
```

Use the **same** Runner secret when recreating either service. `robot status`
should say online. Rebuilding only the server does not update a Balena robot;
deploy matching daemon and Runner images there separately before testing it.

## Run a script and retrieve its artifact

Create a local Python file, for example `hello.py`:

```python
import os
import sys
from pathlib import Path

print("hello from the robot", flush=True)
print("a message on stderr", file=sys.stderr, flush=True)
Path(os.environ["RINGFOUR_ARTIFACT_DIR"], "result.txt").write_text("hello artifact\n")
```

Run it with the robot ID printed by `robot list`:

```bash
uv run --project apps/cli ringfour-cli run hello.py --robot <robot-id>
```

The CLI prints a submission key and execution ID to stderr, then follows the
script's stdout and stderr. A successful process returns 0. A failed process
returns its exit code when it is 1–125, otherwise 1; cancellation also returns
nonzero. The API records the authenticated requester as the actor. Save the
execution ID, then:

```bash
uv run --project apps/cli ringfour-cli execution show <execution-id>
uv run --project apps/cli ringfour-cli logs <execution-id>
uv run --project apps/cli ringfour-cli artifact list <execution-id>
uv run --project apps/cli ringfour-cli artifact download <execution-id> result.txt --output result.txt
```

The displayed state should be `succeeded`, exit code 0, and the downloaded
file should contain `hello artifact`. Download verifies size and SHA-256 and
refuses to overwrite an existing local file. Artifact paths are relative to
`RINGFOUR_ARTIFACT_DIR`; symlinks, special files and escaping paths are rejected.

## Dependencies, retries and cancellation

The default script uses the Runner's installed Python 3.13 and an empty
dependency lock. For third-party packages, make a hash-pinned requirements
lock, then pass it with `--lock`:

```bash
printf 'six==1.17.0\n' > requirements.in
uv pip compile requirements.in --generate-hashes -o requirements.lock
uv run --project apps/cli ringfour-cli run hello.py --robot <robot-id> --lock requirements.lock
```

Runner installs that exact lock using `uv pip sync --require-hashes`; a missing
or incorrect package hash fails preparation. `--python` accepts a Python
version requirement, which must match the interpreter available in Runner.
Package installation requires access to the configured package index.

`--idempotency-key <key>` lets you retry the same submission. Reusing it with
the same script and parameters within the run's 24-hour idempotency window
returns the original execution; changed input conflicts. The generated key is
printed before upload so it can be saved. `--detach` exits successfully after
the Platform accepts the run, without waiting for execution success. To follow
or stop it later:

```bash
uv run --project apps/cli ringfour-cli logs <execution-id> --follow
uv run --project apps/cli ringfour-cli execution stop <execution-id>
uv run --project apps/cli ringfour-cli execution show <execution-id>
```

Stopping submits an operation; inspect until the execution is `cancelled`.
Interrupting a following CLI with Ctrl+C returns 130 and leaves the execution
running. A disconnected robot returns an unavailable error for a new run.
Only one execution can be active on a robot at a time. If Runner loses an
in-flight process, the result is `interrupted_unknown_outcome`, not a replay.

## Limits and retention

Archives and extracted bundles are limited to 1 MiB, each source or lock file
to 256 KiB, and a bundle to 1024 files. Each stdout/stderr stream retains up to
64 KiB; read chunks are at most 16 KiB. An execution can publish at most 16
artifacts, each up to 256 KiB and up to 1 MiB total. Invalid or oversized
artifacts fail collection; partial artifact sets are not published by Runner.
Each organization retains at most 100 revision records and each robot retains
at most 100 executions. The API and Runner refuse new work when their respective
capacities are reached. Expired incomplete uploads are cleaned up after 24
hours; finalized revisions, execution histories, Runner environments and
artifacts are retained until operator cleanup. There is no self-service cleanup
command in this milestone. Deployment storage quotas must also account for
downloaded Python dependencies; per-environment disk usage is not capped by
Ringfour.

## Repeat the isolated tests

These create their own database, organization, robot, device services, network
and volumes, and remove them on exit. They require the current CLI login and
`.auth.env`, Docker and uv. Ports 18085–18087 must be free. The Garage variant
also creates a disposable single-node Garage; neither test changes the live
database or the Balena robot.

```bash
bash tests/e2e/05-scripts.sh
RINGFOUR_TEST_STORAGE=garage bash tests/e2e/05-scripts.sh
bash tests/e2e/05-garage.sh
```

Expect `PASS` for an interrupted upload and retry, execution output and
artifact, replay, a failed script, hash-pinned dependencies, stop, daemon and
API restarts during output transfer, Runner restart reconciliation and
cross-organization denial. The cross-organization check uses a second test-only
signing key with a separate local API process; the main execution uses the
real Auth0 login. See `docs/evidence/05.md` for the recorded results and limits.
