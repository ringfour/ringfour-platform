## Issues caught during verification

The current v2 authoring template exposed an installation validator still hard-coded to manifest v1. Installation now uses validate_manifest, matching start validation; the installation test exercises both versions.

The live-settings command stream could deliver settings before the matching start command. Rejecting that ordering caused repeated reconnects and prevented later starts. The daemon now durably records the authenticated intent; polling/results still require the exact active run credential and verified running container. The recovery test covers late start recording.

Artifact publication now resolves the connection manager's current executor after enrollment; the HTTP app may have started before enrollment and still hold a null initial executor reference. The artifact route test exercises this case and immutable snapshot behavior.

Older E2E fixtures assumed a v1 template release/default. Updated their release increments, valid configuration defaults and settings-enabled API setup to exercise today's template. Superseded failed runs were diagnosed and corrected; they are not counted as passing evidence.
