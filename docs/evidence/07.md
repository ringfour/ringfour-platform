# Evidence — milestone 07 development sessions

Status: **local CLI development execution implemented; full acceptance incomplete**. Discovery started after the
local milestone 06 integration rerun documented in [06.md](06.md). The physical

## Initial scope and decisions to specify

Milestone 07 introduces a mutable, persistent development workspace, explicit
sync and restart, and expiry. It must not modify production revisions or allow
overlapping robot executions. Workspace generations must be complete before
activation, and a stale base generation must be rejected. Source-only updates
reuse the environment; a dependency-lock change must be prepared before it is
activated. The Runner owns workspace and environment data; the Platform owns
session authorization and durable workflow state.

Before implementation, freeze the new Ringfour API, device and Runner contracts,
including schemas, state transitions, errors, limits and fixtures, and specify
persistence and recovery. The existing 05 upload/finalization and 06 operation
and execution contracts are prerequisites; their current behavior must be
inspected rather than assumed. Specific unresolved design choices include the
source transfer representation, deletion and ignore semantics, session expiry
and cleanup bounds, and how interrupted sync and dependency preparation are
reconciled. No external SDK or Agent API is implied by these choices.

## Experimental local listener and grant storage — 2026-11-13

The daemon has an opt-in dedicated HTTPS listener (`RINGFOUR_LOCAL_DEV_ENABLED=true`,
`RINGFOUR_LOCAL_DEV_HOST`, `RINGFOUR_LOCAL_DEV_PORT`, and
`RINGFOUR_LOCAL_TLS_PATH`). It currently exposes only a grant-authenticated
session check; source, output and artifact endpoints are not implemented. The

## Empty session creation and closure — 2026-11-13

operations, exposes session inspection, and accepts closure while the daemon is
offline. The daemon and Runner create or remove the empty session workspace and
the Platform reports `ready` or `closed` only after a matching device result.
Expiry schedules a durable cleanup and remains `closing` until confirmation;
component coverage simulates the device response. Cleanup failures are retried.

## Runner development execution and restart — 2026-11-13

The private Runner can execute a committed development generation using a
stable operation and execution ID. It validates the generation and Python
requirement, rejects an unrelated active production execution, and stops its
own prior execution before restarting. A source-only change reuses the session's
existing uv environment; a changed dependency lock gets a separate one. A
failed dependency preparation preserves previously prepared environments.
Session cleanup waits for its own active process to stop. If Runner restarts
while an execution outcome is uncertain, replay returns the recorded failure
`interrupted_unknown_outcome` instead of running the code again.
