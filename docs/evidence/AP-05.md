## Delivered boundary

- Nine authenticated catalog routes implement publish, Store search, App and
  revision reads, grant/revoke and workspace import/list. Publisher derives from
  authenticated workspace roles. Revisions are immutable; App display metadata is initialized on first publication and updated only by
  listed publications, preventing a private revision from changing public text. No mission/source archive is involved.
- Production C# manifest reader independently validates AP-01 structural and
  semantic fixtures, including target uniqueness, capability overlap, bounded
  flat configuration schemas, defaults/enums and canonical manifest digest.
  Duplicate members/invalid UTF-8 and bounded bodies use the AP-03 reader.
- Existing AP-02 catalog/idempotency tables suffice; **no EF migration**.
  Workspace `FOR NO KEY UPDATE` locking serializes natural App/release/import
  uniqueness without blocking reciprocal grants’ foreign-key reads, and
  idempotency results, with fresh role authorization after acquiring the lock.
  Responses and actor/source IDs are committed atomically. App replay tombstones
  do not expire. JSON member ordering is not part of the replay contract.
- Import uses explicit destination/revision/publisher grant authority for
  unlisted revisions. Share row locks serialize revoke/import decisions;
  committed imports retain source/actor after revocation/expiry. Public App
  visibility never makes its other private revisions visible.
- Registry verification allowlists exact host/repository prefix and binds private
  policies to the publisher workspace, preventing another workspace from
  republishing a known private digest to bypass import/share authority. It rejects
  redirects, bounds responses and complete exchange time, checks actual manifest
  digest/media type and configuration digest/size/OS/architecture. Both OCI image
  and Docker v2 concrete manifests are supported; indexes are refused. All
  targets must verify before catalog writes. Existing retries need no registry.
- New contract/route `POST /v1/device/app-registry-grants` supplies only ephemeral
  anonymous or Bearer pull authority, bound to a negotiated active machine
  session, its nonterminal preparation operation, unexpired deadline, server
  candidate, imported revision and exact image. It rechecks credentials/session
  and durable binding after the remote exchange under the session fence and DB
  locks. Another robot's known operation cannot obtain credentials.
- Token exchange uses only configured realm/service, requests pull-only scope
  and rejects expiry over five minutes. It never returns server Basic secrets.
  Tokens stay out of durable resources, operations, idempotency and App env.
  Grant responses are `no-store`; registry error messages exclude credentials.
  HTTPS is required outside Development. Direct Basic-only private pulls are
  unsupported. Empty registry policy fails closed.
- New OpenAPI/request/response definitions and representative accepted/rejected
  grant fixtures are added before consumers. Implemented routes are marked in
  OpenAPI. Legacy error envelopes remain unchanged; App dependency failures can
  now report `details.retryable` accurately.
- Compose/env-example document one registry policy. No running config or
  deployment was changed. No UI or install/run dispatch is introduced.

Protocol sources reviewed: [OCI Distribution specification](https://github.com/opencontainers/distribution-spec/blob/main/spec.md)
and [Distribution token authentication](https://github.com/distribution/distribution/blob/main/docs/content/spec/auth/token.md).
Registry tokens may be repository-scoped; device digest enforcement and actual
engine pull/create refusals remain AP-07/08/13 responsibilities.
