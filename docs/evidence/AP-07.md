## Contract, authority and persistence

New design was specified before writers in [installation](../apps-installation.md),
using existing App v1 install/configure/update/rollback/observation contracts.
The sole negotiation extension is optional boolean `supports_app_installations`
(default false). Old hello/welcome/negotiation responses stay unchanged; existing
inventory-only peers cannot receive installation commands. API installation work
is opt-in (`Apps:InstallationsEnabled`); the Daemon must also enable App mode.

API Developer/Owner mutations commit permanent idempotency, authorized import,
installation, immutable configuration, candidate and complete device command
before dispatch. Workspace ownership/roles are rechecked for retries. Robot locks
coordinate apply with legacy script/dev/mission starts; diagnostic starts are
refused on robots with App installations. The API rejects invalid full replacement
configurations without merging defaults. Rollback requires a previously applied
retained configuration from the same installation. One (robot, App) identity is
retained, including repair after a failed initial install. Distinct Apps coexist.

EF migration `20261123221503_AppInstallationCommands` adds command/first-dispatch
columns to existing operations and installation support to negotiated inventory.
A database trigger protects command/first-dispatch evidence. Existing AP-02
schema holds installation/configuration/history and permanent idempotency. A
never-dispatched expiry creates no device observation; possibly delivered work
stays uncertain until reconciliation. The worker rechecks active negotiated
session, namespace and credential validity for dispatch. Machine manifest/report
routes are separately authorized by exact operation and enrollment/session.

SQLite 0018 journals preparation and immutable terminal reports. Fresh Agent
compatibility precedes scoped pull; the Daemon validates manifest canonical hash,
target/configuration, grant identity/repository/expiry, engine platform and image
entrypoint/non-root metadata. No human/registry credentials persist in command,
configuration, journal/outbox or App environment. Pull/inspection is the only
engine side effect. Configure checks the installed image without pulling again.
Application rechecks deadline, generation and local App/legacy/dev exclusion in
one SQLite writer transaction, switches the installed binding and appends its
terminal report atomically. Failed preparation retains the prior installed binding.
Shutdown waits for in-flight pull/mutation work before releasing the lifetime
writer fence; a closed executor cannot apply later work. Disk exhaustion has a
sanitized storage_unavailable result.

Hosted observations validate namespace/IDs/generation, exact image/config/operation,
phase progression and application proof while idle. Projection/stream receipt
commit together. Same report/content replays original receipt; conflicting report
IDs/sequences or fabricated application are refused. Terminal replays cannot
replace newer installed state. The observation route currently implements the
installation family; run observations remain AP-09.

An independent supplementary Unicode/line-separator fixture revealed the C#
writer's supplementary-character escaping differed from canonical UTF-8. C#, Node,
CLI and Daemon now share exact fixture bytes/digest, and configuration byte limits
use canonical UTF-8. Existing ASCII/image/template pins remain unchanged. Public
schemas are vendored into the independently packaged Daemon and checked against
contracts; no API/CLI private implementation is imported.

```sh
uv run --project apps/daemon python tests/e2e/ap07-install.py
```
