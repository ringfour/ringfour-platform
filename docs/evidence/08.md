## Initial daemon outbox — 2026-11-13

The daemon now has a 4096-event logically bounded SQLite queue, persistent
sequence and acknowledgement state, and a retrying HTTPS/HTTP Platform delivery
loop. Event append is explicitly transactional; capacity exhaustion is surfaced
to its caller. A savepoint prevents a failed insert from consuming a sequence.
The queue is **not yet connected to operation state changes**: its capacity policy
must first reserve a safe path for stop and cleanup operations. The 4096-event
limit bounds event count and event payload size, not total SQLite or filesystem
bytes. Nothing here claims the host cannot exhaust its disk.


The isolated integration runs a real daemon, API and PostgreSQL with Auth0

the entries survived, then restarts the API and verifies both events were
ingested once and acknowledged locally. This is not evidence of automatically
