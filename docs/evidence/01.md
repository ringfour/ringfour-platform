## Decisions and deviations

- **No `Idempotency-Key` in 01**: per the starter schema, idempotency-record
  persistence is specified with milestone 03. Membership add is naturally
  idempotent-safe via the composite PK (duplicate → 409 `conflict`).
- **Role storage**: roles persist as PascalCase strings with a check constraint;
  the public contract emits lowercase (`owner`/`developer`/`operator`) via
  snake_case JSON enum conversion. Internal representation only.
- **Test signing**: tests inject a PEM RSA key via `Auth:Test:*` configuration;
  `ValidateAuthConfiguration` refuses it in Production and refuses startup
  without Auth0 settings otherwise.
- **Last-owner concurrency**: membership demote/remove locks the organization
  row (`SELECT … FOR UPDATE`) before counting owners; verified by a concurrent
  test where exactly one of two owner demotions succeeds.
- **CLI**: single credential slot per tenant/audience in the keyring;
  `--no-browser` added to `login` for SSO-safe second-account and headless use.
- **Console signup**: `screen_hint: "signup"` button (New Universal Login).
- **User resource** exposes only `id`/`created_at`; no email or Auth0 sub is
  stored or returned (subject stability verified instead).
