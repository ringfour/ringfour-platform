# AP-17 implementation evidence

Status: automated integrated settings/files acceptance passed in an isolated
real API/Daemon/runtime process fixture. A live virt2 run confirmed settings
and start/stop, but exposed a reference-app summary-artifact path issue;
browser acceptance remains pending. The passing report is
[`ap17-process.json`](ap17-process.json). Its authorization checks use
Development-signed test principals, not real Auth0 users.

The fixture published and installed a real App image from the pinned runtime
wheel/template, applied initial and live settings, covered invalid/idempotent/
conflicting/stale/rejected writes, replaced API and Daemon processes during
pending delivery, verified no duplicate application after recovery, checked
cross-run artifact hashes and pagination, and downloaded a verified report
through the CLI. This confirms the backend/runtime path without claiming a
real robot or browser pass. A separate bonus live virt2 attempt published a
test release. That initial attempt exposed a CLI request bug: absent
`share_id` was omitted instead of sent as `null`. The CLI now sends the
schema-required nullable field; its focused tests pass (4/4), and live
installation succeeded. On virt2, the real App applied initial and live
settings, emitted all 20 IMU samples, and completed a start/stop lifecycle.
Its final summary artifact publication failed because the pinned Robot Check
example passes relative path `summary.json` to `publish_file` instead of the
file under `RINGFOUR_ARTIFACT_DIR`. Thus AP-17 Platform settings, CLI install
and isolated Files/artifact integration passed, but full live artifact
acceptance remains open pending a corrected, republished example. No motion
was requested. Floating-point configuration follow-up AP17.F1 is deferred.

## Studio and CLI implementation slice

The Console now has workspace-scoped App detail URLs with Overview, Settings,
Files and Activity sections and URL-backed installation selection. The Apps
library presents searchable App rows with concise robot assignments instead of
repeating the configuration editor in each inventory card. Overview groups
release identity, selected robot connectivity, compatibility, current
execution and permitted start/stop/update actions; an ambiguous multi-robot
target now explicitly asks for a selection. Home groups active App
assignments by App identity, links each robot target, and offers one setup path
when the workspace has no robots, active runs or pending attention. The
Settings view reads/writes the revisioned settings API and distinguishes
next-start selection, pending application, App-confirmed values and rejection
outcomes. It presents next-start selection separately from values last
confirmed by the current process, disables fields during unresolved requests,
and protects unsaved startup/live edits when navigating within Studio. Files
reads the paginated cross-run endpoint, supports installation,
run and path-prefix filters, synthesizes folder navigation from loaded result
pages, links to source runs and verifies downloaded size and SHA-256 through the
existing authorized content route. Activity reads the same workspace App
Logbook, presents readable event titles and context, keeps event/operation IDs
in expandable details, and links to exact runs. Empty, filtered-empty, retry
and stale-snapshot states are distinguished.

The CLI now provides `app settings show`, `app settings set --file ...`, and
cross-run `app artifacts --app ...` with workspace, robot, installation, run
and path-prefix filters. Existing exact-run artifact listing and downloads
remain available. Authoring documentation covers manifest v2, environment
mapping restrictions, live-settings idempotency, data limits and the
non-persistent per-run artifact directory. A human guide is in
[`docs/human-testing/AP-17.md`](../human-testing/AP-17.md).

Outcome: the Console TypeScript check, Biome checks, CLI Ruff check, CLI help
smoke and whitespace check pass. Biome reports three CSS specificity warnings
in the workflow stylesheet; no TSX errors remain. Component/browser tests were
not run in this pass.
