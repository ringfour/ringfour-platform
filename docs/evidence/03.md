## Freeze points (configuration)

- API: heartbeat interval 15 s, offline threshold 45 s (server receive time),
  operation deadline 60 s, sweeper interval 2 s, idempotency TTL 24 h,
  idempotency key max 200 chars.
- Daemon: reconnect backoff 1 s → 30 s cap with ±20 % jitter, enrollment poll
  5 s, reconcile delay 20 s, outbound queue bound 128.
- WebSocket close statuses: 4401 (credential rejected / revoked), 4402
  (unsupported protocol version), 4409 (protocol violation incl. stale/gapped
  sequence, robot mismatch, conflicting operation id, session replaced).

## Integrated acceptance (real Auth0, real processes)

`tests/e2e/03-connectivity.sh` — PASS (run 2026-11-10; repeatable; resets the
daemon volume first):

1. Owner enrolls a fresh robot (same flow as 02). The daemon notices the
   enrollment by itself (5 s poll) and connects; `ringfour robot status`
   reads `online` with daemon version 0.1.0 and protocol v1.
2. Owner creates a diagnostic operation with curl; it is dispatched over the
   live WebSocket and reaches `succeeded` with `{"noop": true}`.
3. Idempotency: same key + body replays the same operation (200, identical
   id).
4. Network interruption: `docker network disconnect` the daemon container →
   status goes `offline` after the 45 s freshness threshold; an operation
   created meanwhile stays `queued`; `docker network connect` → daemon
   reconnects through its backoff and the queued operation runs exactly once.
5. Daemon restart: reconnects, subsequent operations succeed, and the local
   SQLite holds exactly one `device_operations` row per operation id (dedup
   across restart).
6. Revocation: the owner revokes the daemon's credential → the platform
   closes the WebSocket immediately, the daemon retries with backoff and is
   denied, status reads `offline`, and the enrolled identity is retained.

## Decisions and deviations

- **welcome/error message types**: see Contracts above (new design extending
  the architecture's enumerated set).
- **Credential in headers, not query**: `x-ringfour-credential-id` /
  `x-ringfour-credential-secret`; query strings land in access logs, headers
  do not.
- **Replacement policy**: an accepted hello unconditionally replaces the
  stored session (upsert on `robot_id`); the previous socket is told
  (`session_replaced`) and closed with 4409. All presence writes are fenced
  by `session_id` in the WHERE clause.
- **Close without handshake wait**: revocation and error closes use
  `CloseOutputAsync` so the owner's HTTP response never blocks on a (possibly
  dead) device's close handshake. (Found as a real deadlock in tests.)
- **Online is derived, not stored**: `online = last_seen within 45 s`,
  computed at read time from server receive time; `last_seen_at` persists
  across API restarts for display.
- **Command dispatch is at-least-once**: commit before dispatch; sweeper
  redelivers queued operations to live sessions every 2 s; reconnect replay
  covers dead sessions; the daemon's SQLite `device_operations` is the dedup
  record (identical content replays status, conflicting reuse of an operation
  id is a protocol error that closes the connection).
- **Reconciliation**: on connect the platform replays every nonterminal
  operation, so the daemon marks any local nonterminal record absent from the
  replay as `failed/superseded` after a grace delay (20 s).
- **Idempotency record scope**: principal (local user id), route (literal
  template), target (robot id), key; fingerprint = SHA-256 of the raw body;
  the record stores an operation reference only — one-time credential
  responses are never persisted for replay.
- **Hello requires protocol version 1**; the daemon announces
  `supported_protocol_versions` and the platform picks the frozen 1.
- **Daemon enrollment poll**: the connection manager polls enrollment every
  5 s so enrollment through the daemon's HTTP API (after boot) connects
  without a restart.
