# AP-02 implementation evidence

## Implemented in this slice

- The checked-in chain now contains 35 migrations. The current chain builds the
  Platform schema from empty PostgreSQL and includes the AP-02 Apps migration.
  EF generated an idempotent script at `/tmp/ringfour-apps-persistence.sql`.
- `apps/api/tools/IdentityTransfer` exports only users, organizations and
  memberships into versioned JSON and restores those rows with existing IDs.
  Export uses a repeatable-read snapshot and refuses to overwrite an existing
  bundle. Restore validates IDs, Auth0 subject uniqueness, membership
  references/roles and organization ownership; it refuses nonempty identity
  targets and uses a serializable transaction.
- Added `AppsPersistence` EF migration and snapshot for Apps, revisions, shares,
  imports, installations, configuration revisions, operations, runs, idempotency
  replay records and robot execution slots. Scoped composite foreign keys tie
  installations, runs and operations to their robot/workspace. Database
  triggers claim/release a robot slot from both legacy `script_executions` and
  App `app_runs`, and the migration backfills currently active legacy rows.
- Added Daemon SQLite migration `0015_apps.sql`. It leaves the legacy identity
  table layout intact, creates a durable per-enrollment namespace (backfilled
  for existing enrolled devices), stores App installation/run and bounded
  output state, stores only run credential hashes, and persists sequenced
  inventory/observation outbox rows. A single local execution slot is shared
  between App runs and legacy `script_sync`, with active legacy rows backfilled.
  Existing enrollment, device operations,
  Logbook, script sync/output, and interaction data are not reset.
- New Daemon enrollment commits its generated deployment namespace in the same
  SQLite transaction as the machine identity row.
