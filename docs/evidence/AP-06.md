## Implementation and authority

- `app init` extracts only a checksum-matching archive into a new destination,
  refusing an existing destination. The caller selects App identity/repository.
  No robot/workspace context is copied.
- `app validate` independently enforces manifest/configuration semantics,
  bounded UTF-8, duplicates, Unicode/safe integers, unique platforms and safe
  explicit file paths. Final manifests reject tags/unsupported targets.
- `app build` stages only declared regular files and verified local AP-04
  dependency inputs, checks copied input hashes again, and records source
  fingerprint plus immutable local image IDs. Secret/context/state files and
  symlinks cannot be declared as inputs; undeclared files never enter context.
- `app publish` uses Docker login and existing Auth0/keyring configuration,
  verifies local image IDs, pushes a concrete platform-specific manifest,
  verifies remote manifest digest/platform, freezes the manifest, and posts
  AP-05 metadata last. The server independently verifies raw config bytes and
  publisher policy. Frozen retries reuse identical input without repush or
  requiring registry availability before API replay. Changed content requires
  a new release. Independently prepared immutable manifests are supported.
- JSON results/errors have controlled exits; legacy CLI commands and default
  workflows remain until cutover. Auth0/registry credentials never enter build
  files, command arguments, frozen manifests or App env. Source fingerprint and
  API idempotency remain separate identities.
- Robot Check has one plain entrypoint and one field, `sample_count` (1–20,
  default 1), matching AP-01. It uses only verified read-only SDK `imu()` NET
  calls, requires advancing finite stamps within a bounded wait, supports stop
  signals, emits JSON and optionally invokes the separate Logbook client.
  SDK errors are sanitized into a structured failure event/nonzero exit.
  Runtime delivery/credentials remain AP-10; installation/execution is AP-07+.
