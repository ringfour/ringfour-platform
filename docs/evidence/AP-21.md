builders define canonical links; no routing dependency is needed.

| Canonical route | Context |
| --- | --- |

| `/apps`, `/apps/A/overview`, `/settings`, `/files`, `/activity` | workspace, robot filter, exact installation |
| `/app-store`, `/app-store/A` | workspace, release, robot, operation |

`/` normalizes to Home; `/logbook` and `/logbook/U` normalize to `/runs`

show recovery instead of Home. Fixed enrollment routes precede robot IDs.
Normal links preserve browser new-tab/copy-link behavior. Only unmodified local
link activation uses client navigation and the existing dirty settings guard.
Workspace changes clear resource context and return to the parent collection.

## Implemented behavior

- One Studio shell and workspace selector, ordered main destinations, real links,
  named route builders and route parsing. Unknown routes show recovery.
- Shared location handling checks unsaved edits before publishing link, Back or
  Forward navigation. History indexes restore rejected transitions without
  replacing the visible resource; accepted Back restores list context/scroll.
- Enrollment and credentials routes replace Fleet's same-URL Manage mode.
  Pairing, one-time enrollment/rotation secrets and targeted revocation remain.
- Robot inventory reads `inventory.current` or explicitly qualified
  `last_successful`, fixing the zero-capability display bug. Home shows compact
  robot work rows, grouped failures and short recent activity.
- Store cards, direct listings, private imports, robot picker, automatic
  compatibility, same-release Open App and durable operation URLs/candidates.
- Apps membership follows current installations, grouped with a robot filter;
  detail sections share identity and exact target context. Removed installations
  remain readable through history and Files.
- Update/rollback/uninstall review uses existing guarded mutations. Applied
  configuration history and current negotiated uninstall support are now exposed
  as read-only API fields/endpoints (new interface design, no new tables/tasks).
  Publisher names and trusted official labels come from the server.

  SHA-256 before creating a temporary blob URL. SVG/HTML remain download-only.
- Run-grouped Activity, canonical Logbook filters/loading/unavailable states,
  secondary Timeline navigation and retained historical event rendering.
- Owner-approved deployable static Studio target with pinned Nginx, deep-link
  fallback, asset 404s and same-origin bearer-authenticated API proxy. Local
  Compose explicitly continues to select its development build target.

### Slowdown investigation and changes

During this pass the owner reported the whole frontend was slow, then explicitly
allowed the agent to restart as needed. This overrides the ordinary workspace
stack-operation restriction for this investigation. Only Console was rebuilt and
recreated; API, database and virtual stack were left running.

The deployed Console was a Vite/React development server. Its JavaScript included
large development dependencies and development-time effect replay. The API and
host were not saturated: a 10-minute live API log sample showed common App/robot
reads at roughly 1.8–2.8ms median, while `/v1/me` took 212ms median (384ms maximum).
The UI's shared Home/Robots loader waited on that unused profile attribution,
member names and undisplayed per-run artifact counts. Those reads are removed
from these screens. Timeline explicitly opts into attribution; historical detail
readers remain separate. No general cross-workspace cache was added.

Local Compose now selects the existing production target, passes public Auth0
SPA settings at build time and maps the same host port 5173 to Nginx port 80.
Nginx compresses JS/CSS/SVG and retains hashed-asset caching. The development target
and `npm run dev` remain opt-in source-preview workflows. New regression coverage
asserts Home does not request profile/member/artifact data and Timeline still
requests its attribution. The before/after fixture records zero full-document
reloads during client navigation.

| Fixture action | Before p50 | After p50 |
| --- | ---: | ---: |
| Home → Robots | 350.0ms | 150.0ms |
| Robots → Home | 349.8ms | 149.9ms |
| Overview → Settings | 66.5ms | 66.7ms |
| Settings → Overview | 66.8ms | 66.7ms |

These are five Playwright samples per warm action in the actual development
components, with browser-only Auth0/API fixtures, 5ms API delay and 220ms profile
