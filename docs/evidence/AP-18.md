# AP-18 implementation evidence

Status: API/Daemon/CLI implemented and component checks passed. Disposable
process acceptance is recorded below. Live publisher configuration, the remaining
failure/recovery matrix and human acceptance remain open. Studio controls are AP-21.

## Implemented

- Public `listed` publication requires both workspace developer authority and
  the trusted `Apps:OfficialPublisherOrganizationId` entitlement. CLI publication
  defaults to private `unlisted`; public automation explicitly supplies `--yes`.
  The server derives the official publisher label.
- A publisher may install its own private release without a share. Private
  imports into another workspace still require a destination-bound share.
- Existing update/rollback operations retain immutable release/configuration
  snapshots and keep the previous binding on staging failure.
- Negotiated uninstall uses durable operations and observation outboxes, exact
  binding guards, idle checks and Start exclusion in API and Daemon. Removal
  preserves history, files and shared images. Reinstall creates a new identity.
- Migrations: `20261125140000_AP18OfficialUninstall` and
  `20261125150000_AP18RemovalHistory`. The second extends Logbook constraints
  for `app.installation.removed`; the history response schema includes this event.
- Acceptance found and corrected an omitted observation-kind enum, a stale
  vendored schema, own-private-release imports, stale-uninstall failure reporting
  and the removal Logbook database constraint.

## Disposable process acceptance

`tests/e2e/ap18-lifecycle.py` passed with the actual API, PostgreSQL 18,
registry, pinned Agent implementation, two Daemon processes and Docker Engine.
The fixture creates its own containers and never changes the running stacks.
It inherits the AP-07 API/Daemon replacement and failed-update/rollback checks.
It then verifies ordinary public publication refusal, official discovery,
import and installation in a separate workspace on a second enrolled robot,
private-release isolation, CLI uninstall, retained configuration retrieval,
new installation identity on reinstall, and preservation of the second robot's
binding. The Agent fixture has ROS disabled: no sensor or motion claim is made.

[ap18-process.json](ap18-process.json).

publisher the explicit official entitlement. It checks three principals,
