# AP-08 — owner-scoped engine prerequisite

Implementation and isolated component/real-engine/process acceptance passed on
24 November 2026. AP-07 explicitly depends on AP-08 in the backlog; the user's
request to continue AP-07 authorized this prerequisite first. No Platform or
virtual stack was rebuilt, reloaded or restarted. Deployment/topology remains
an operator/AP-08V gate. [Operator checks](../human-testing/AP-08.md).

Contract-first new design: [engine policy](../apps-engine.md). Docker Engine
REST v1.46 uses httpx pinned to 0.28.1 over an operator-provided Unix socket.
No Docker SDK, subprocess engine context or TCP production engine endpoint is
introduced. Actual engine metadata supplies target OS/architecture. App mode
readiness/status do not call Runner; legacy mode remains available.

SQLite 0017 adds durable create/start boundaries alongside AP-02 run/output
records. A lifetime file lock fences the enrolled database/namespace. Intent
precedes create; start intent precedes start; replacement reattaches to exact
labels, immutable image ID and owner network. A created container's configured
network is checked before Docker materializes its attachment ID; running state
requires the actual network ID. Ambiguous possibly-started/absent work is never
relaunched. Terminal output is sealed before exact-ID removal. Retention gaps
are flagged as truncation without replacing a saved prefix. No prune exists.
A non-root image user/entrypoint is required; owner policy drops capabilities,
sets no-new-privileges, CPU/memory/PID/log limits and a single network. No host
bind, socket, privilege or command/entrypoint override is supplied. Configuration
is copied before start as a root-owned 0444 file. Rootfs remains writable because
Docker refuses archive injection into a read-only rootfs; the non-root App cannot
modify that root-owned configuration. Runtime credentials remain AP-10.
