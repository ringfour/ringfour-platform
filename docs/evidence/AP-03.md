# AP-03 — observed capability inventory

Status: implementation and isolated protocol acceptance passed. Deployed
Platform/virtual reload and re-enrollment checks remain operator actions.

## Implementation

- Daemon obtains fresh inventory through the Agent's existing JSON-RPC protocol
  1 hello over Unix or TCP WebSocket, with a bounded timeout and 1 MiB welcome
  limit. Additional description/features are ignored; unknown well-formed
  capability/instance IDs remain observable. No sensor/motion call is sent.
- Engine platform is supplied by infrastructure from `docker info`; x86_64 and
  aarch64 normalize to amd64 and arm64. It is never inferred from Daemon process
  architecture. Native prerequisites require operator-verified facts.
- `check_fresh` returns structured compatibility/refusal results after a new
  hello. Cached inventory cannot satisfy the gate. App install/start callers
  will consume this in AP-07/08/09; AP-13 retains the actual zero-pull/create
  integrated refusal gate because those engine paths do not exist yet.
- Separate session negotiation, inventory upload, robot App status and revision
  compatibility preview are implemented against AP-01 contracts. Machine
  credentials and current session fence inventory writes; workspace membership
  and independent publisher/listing/share/import authority fence reads.
- PostgreSQL migration `AppInventory` persists namespace/session/projection and
  canonical report hash/receipt deduplication. Device SQLite migration 0016
  retains the last successful Agent observation. Outbox/projection updates are
  atomic; lost HTTP acknowledgements and reconnects resend the same body/IDs.
- API JSON Schema validators use a private registry and bounded UTF-8/duplicate
  member checks. Validators are compiled once and use packaged contract files.
  Implemented App endpoints opt into the v2 error envelope, including bounded
  messages and `details.retryable`; legacy endpoints keep the v1 envelope.
  API Docker build context is now the repository root so publication includes
  schemas; all existing Compose/e2e API build callers were updated.
- Virtual launchers pass the engine platform and instance-specific Agent URI.
  Existing local Base101 profile edits and gitlink were left untouched.
