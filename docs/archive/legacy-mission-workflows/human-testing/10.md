# Milestone 10 human acceptance guide

The stationary read-only Base101 UI, browser reconnect, and UI-server
continuity checks have been exercised on the current live stack and are
recorded in `docs/evidence/10.md`. Milestone 10 remains in progress because
authenticated remote Console access (10b) is not implemented or tested. Keep
the existing `10-robotics-e2e.md` gate intact.

The Runner was reloaded on 18 November with an updated `ringfour-ui` wheel and
Runner-owned port assignment/readiness. Each Runner reload ended the previous
Base101 execution; the current revision with the refreshed wheel pin is
running as `cddc3be1-8276-4562-904a-714c5706cdc2`. Its UI is available at
`http://localhost:7860/`. The readiness route's `ready` state was confirmed;
`starting`, `unavailable`, and `ended` still need checks.
The Platform session/bootstrap API and migration are live and their direct API
handshake was checked. After the owner reloaded both stacks, the UI socket
accepted a credentialed handshake and the Runner reported a live no-motion UI
as `ready`. End-to-end daemon status propagation still needs observable
evidence. The transport does not yet carry browser HTTP/SSE traffic.

## Local 10a checks

1. After the owner reloads the rebuilt `ringfour-virtual` Runner image, publish
   a mission whose hash-checked lock pins the vendored `ringfour-ui` wheel,
   Ringfour SDK wheel, and all transitive Gradio dependencies.
2. Start a stationary/read-only mission with a Gradio map or status view.
3. Open the local UI and confirm assets load, timer updates continue, and
   interactive callbacks behave as intended.
4. Close the browser, reopen it, and confirm the mission did not stop or
   restart. Repeat with the UI server stopped while the headless mission
   remains active.
5. Confirm Gradio public sharing is disabled and the default listener is
   loopback-only.
6. Record exact SDK/Gradio/package versions, commands, browser requests,
   execution ID, observed process states, and sanitized output in
   `docs/evidence/10.md`.

## Remote 10b checks

After 10a passes and the authenticated transport and Console entry point exist,
test organization and role denial, execution-specific routing, membership and
credential revocation, reconnect, multiple viewers, slow clients, UI crash,
browser-origin isolation, secret leakage, and teardown after execution end.
Record remote results independently from local checks. Do not treat an iframe
or same-origin proxy by itself as evidence of isolation.
